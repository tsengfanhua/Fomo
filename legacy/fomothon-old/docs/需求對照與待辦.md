## 2. 實作時自行做的決定（請團隊確認）

1. **教師與課綱資料都用合成資料，沒有爬真實網站。** 原因有兩個：決賽文件不能出現校名與教師姓名；爬蟲需要先確認對方網站的使用規範。系統保留了接真實來源的位置（`FOMO_SYLLABUS_BASE_URL` 與 `src/inventory/campus.js` 的解析器），但真實網站的頁面格式需要另寫解析。
2. **修課證據的計分公式是自訂的**：成績 ×（0.70＋0.20×課綱涵蓋度＋0.10×實作比重）。討論文件說評估機制還要再討論，所以所有係數都放在設定檔。初賽簡報列的「修課時間（近期）」沒有納入計分，只保留為證據的學期資訊。
3. **自述證據上限 69 分**（最高只到初階），而且在競賽需求比對時不算達標。這比討論文件寫的更嚴，目的是讓「待驗證」有實際效果。
4. **英文用 CEFR**，依技能編碼標準文件的建議；修課成績不推估英文等級。
5. **上位技能可由下位技能推估**（例如有 JavaScript 就推估前端開發，×0.9、視為推估）。討論文件沒有提到，是依編碼標準文件「用階層做缺口比對」的建議加上的。
6. **LLM 不參與計分與資格判定**，延續初賽簡報「決策為規則式」的說法；LLM 只做辨識、語意萃取、在合法清單內選下一步、潤飾說明。
7. **技能指標庫先收 46 項**，編碼標準文件建議 100–200 項。擴充只需要編輯 `data/seed/skills.json`。
8. **產品名稱沿用 Fomo鬆／FomoThon**。討論文件的架構圖寫的是「FOMOSON AI 助理」，如果要改名，改 `public/index.html` 與 `README.md` 即可。
9. **MCP 協定層自行實作、不用官方 SDK**，以維持執行期零相依；改以官方 SDK 的 client 做互通測試。MCP 只開放唯讀工具，送出邀請仍在系統內確認。
10. **MCP 的 HTTP 端點用個人權杖**，不是規範建議的 OAuth 2.1；預設關閉。
11. **路由表的預設**：`claude-tiered` 讓任務辨識用 Haiku 5.5、萃取與說明用 Sonnet 5.5，未通過檢核才升級；單一端點模式仍預設 `claude-opus-5-5`。要不要這樣分流，應以多模型評比的結果決定。
12. **修正別名比對規則**：資料品質規則發現「JS」會誤中「Node.js」「Vue.js」，改為英數別名不可緊接在「.」之後。修正後，後端課程（IM260）不再被判定為教 JavaScript；Agent 評測結果不變（27/27）。
13. **品質不合格的課綱推得的技能降為「推估」**（週數不足 16 週、教學目標過短、評量權重不是 100%、含可疑內容）。目前只影響惡意測試課綱 GE199。
14. **標準答案採共識制**：兩位標註者都標的才算正例，分歧項不計分；沒有由開發者裁決分歧。
