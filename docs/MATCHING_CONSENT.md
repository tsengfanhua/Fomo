# 媒合資料同意閘門（F3）

## 原則

「開放媒合」與「確認能力檔案」是兩項不同的條件。學生只有在同時符合下列條件時，才會進入隊友搜尋與邀請流程：

1. `users.attrs.openToMatch === true`
2. `users.attrs.hoursPerWeek > 0`
3. `profiles.state === 'confirmed'`
4. `profiles.stale === 0`

能力檔案新增或更新後會回到草稿／過期狀態，必須由本人重新確認。任何一項條件不符合，都不得以其能力資料參與媒合。

## 強制執行位置

- `src/agents/teammate.js`：每一輪 peers.search 都先套用資格閘門，避免精準、補查、潛力探索出現不同的隱私標準。
- `src/agents/competition.js`：補位覆蓋率只計算已開放媒合且能力檔案已確認、未過期的學生。
- `src/safety/guard.js`：邀請寫入前重新讀取資料庫狀態，避免搜尋完成後對方撤回同意或檔案過期造成競態問題。

## 行為

- 候選人不足時繼續既定搜尋輪次，但不放寬同意條件。
- 最終候選人不足時回報不足，不以未同意資料補足數量。
- 送出邀請時重新檢查，不依賴先前搜尋結果。
- 搜尋事件只記錄排除數量，不記錄被排除者的個人資料。

## 測試

`test/agents.test.js` 包含草稿檔案、過期檔案不得搜尋，以及不得邀請的回歸測試。
